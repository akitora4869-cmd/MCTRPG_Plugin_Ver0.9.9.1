# TRPGCharacter 初心者KP向け仕様書
## Paper 1.20.1 / Java 17

この文書は、TRPGCharacterを使って初めてKPをする人向けの簡易マニュアルです。
現在のセッション管理は「1サーバーにつき同時に1卓」です。

---

## 1. 最初にすること

### KP権限を付ける

管理者(OP)が次を実行します。

```text
/kp <プレイヤー名>
```

例:

```text
/kp Taro
```

KPに登録されたプレイヤーはKPブックを利用でき、セッション管理などのKP向け機能を使えます。

---

## 2. セッションを作る

KPが次を実行します。

```text
/create session <セッション名>
```

例:

```text
/create session 悪霊の家
```

成功すると「悪霊の家」が現在のセッションとして登録されます。

### 注意

- 同時に作成できるセッションは1卓だけです。
- すでに開催中の場合、別のセッションは作成できません。
- 開催情報は `session.yml` に保存されるため、サーバーを再起動しても維持されます。

---

## 3. PLに参加してもらう

PLは次を実行します。

```text
/session join
```

参加すると、そのPLが現在のセッション参加者として登録されます。

退出したい場合:

```text
/session leave
```

KP自身は探索者参加者には登録されません。

---

## 4. 参加者を確認する

KPは次を実行します。

```text
/session list
```

現在オンライン中の参加探索者について、以下を確認できます。

- 探索者名
- Minecraftプレイヤー名
- HP
- MP
- SAN

KPブックを開き直す場合:

```text
/kpbook
```

KPブックにも現在のセッション名と参加人数が表示されます。

---

## 5. セッションを終了する

セッション終了時にKPが次を実行します。

```text
/session end
```

実行すると、

1. セッションを終了
2. セッションログを保存
3. セッション参加登録を解除

が行われます。

### 探索者データは消えません

`/session end` を実行しても、以下の探索者情報は削除されません。

- 能力値
- 技能値
- HP
- MP
- SAN
- 探索者名

キャラクターそのものを初期化するコマンドとは別機能です。

---

## 6. セッションログ

セッション終了時、自動的に次へYAML形式で保存されます。

```text
plugins/TRPGCharacter/session-logs/
```

ファイル名の例:

```text
20260828-210530-悪霊の家.yml
```

ログには主に以下が残ります。

- セッション名
- 開始日時
- 終了日時
- セッションを作成したKP
- セッションを終了したKP
- 参加したプレイヤー
- 参加・退出日時
- 終了時にオンラインだった探索者の名前
- 終了時HP / MP / SAN
- CREATE / JOIN / LEAVE / END の履歴

ログはセッション終了後の確認や記録保存に利用できます。

---

## 7. 情報ポイントを準備する

アーマースタンドを情報ポイントとして使えます。

アーマースタンドを見ながら:

```text
/clue mark <clue-id>
```

例:

```text
/clue mark blood
```

`clues.yml` に登録されている情報をそのアーマースタンドへ設定します。

### 周囲をまとめてシナリオ用に設定

```text
/clue setup 20
```

KPから20ブロック以内のアーマースタンドを、

- 透明化
- 破壊不能化

します。

個別の操作:

```text
/clue hide 20
/clue show 20
/clue protect 20
/clue unprotect 20
```

目星成功者には、透明な情報ポイントの場所へ白色パーティクルが表示され、
右クリックすると情報を読むことができます。

---

## 8. PL会議などで時間を止める

```text
/stop time
```

KP/管理者以外の行動やMobなどを停止させるための機能です。
もう一度実行すると解除されます。

Minecraft標準の `/stop` とは別で、必ず `/stop time` と入力してください。

---

## 9. 探索者が死亡した場合

死亡した探索者はスペクテイターモードになります。

KP/管理者は次で復活できます。

```text
/status revive <プレイヤー名>
```

探索者シートは死亡時にも保持されます。

---

## 10. よく使うKPコマンド早見表

```text
/kp <player>                  KP登録
/kpbook                       KPブックを開く
/create session <名前>        セッション作成
/session list                 参加者確認
/session end                  セッション終了＋ログ保存
/clue mark <id>               情報ポイント登録
/clue setup <範囲>            アーマースタンド透明化＋保護
/clue show <範囲>             アーマースタンド再表示
/clue unprotect <範囲>        保護解除
/stop time                    PL会議用時間停止/解除
/status revive <player>       探索者復活
```

PLによく案内するコマンド:

```text
/status
/session join
/session leave
/roll 1d100
```

---

## 11. 初心者KP向け・開始から終了まで

### 開始前

```text
/create session 悪霊の家
```

必要な情報ポイントを配置して:

```text
/clue mark blood
/clue setup 20
```

### PL集合後

PL全員に:

```text
/session join
```

を実行してもらいます。

KPは:

```text
/session list
```

で参加状況を確認します。

### セッション中

KPブック:

```text
/kpbook
```

PL会議など:

```text
/stop time
```

### 終了時

```text
/session end
```

これでログが保存されます。

---

## 12. トラブル時

### 「現在開催中のセッションはありません」

KPが先に:

```text
/create session <名前>
```

を実行してください。

### 「すでにセッションが開催中」

現在の卓を確認し、終了する場合:

```text
/session end
```

その後、新しいセッションを作成します。

### `/clue` が動作しない

最新版JARがサーバーの `plugins` フォルダに入っていることを確認し、
JAR差し替え後はサーバーを完全に再起動してください。

### コマンドがUnknown commandになる

古いJARが読み込まれている可能性があります。
`plugins` フォルダ内に古いTRPGCharacter JARが複数入っていないか確認してください。

# 追加仕様: シナリオ時計とBossBar

## セッション作成時に時間帯を指定

現在はセッション名だけではなく、最後に時間帯を入力します。

```text
/create session 悪霊の家 夜
```

使用できる時間帯:

```text
早朝
朝
昼
夕方
夜
深夜
```

作成直後はシナリオ時計が停止した状態です。

## BossBar

セッション作成中は画面上部にBossBarが表示されます。

表示例:

```text
悪霊の家 | 夜 21:35 | ▶ x60
```

時計停止中:

```text
悪霊の家 | 夜 21:35 | Ⅱ 停止
```

BossBarは、その時間帯の中でどこまで時間が進んだかもゲージで表します。

## 時計を開始する

```text
/session time start
```

## 時計を一時停止する

```text
/session time pause
```

## 再開する

```text
/session time resume
```

## 時間帯を直接変更する

```text
/session time 深夜
```

時間帯の開始時刻へ移動します。

## 時間を手動で進める

```text
/session time add 30
```

30分進みます。

```text
/session time add -10
```

10分戻ります。

## 時計の速さ

```text
/session time speed 1
```

現実1分でゲーム内1分進みます。

```text
/session time speed 60
```

現実1分でゲーム内60分進みます。

設定可能範囲は1～600です。

TRPGでは、常時高速で時計を動かすよりも、
普段は停止または低速にし、探索や移動が発生した時に
`/session time add 30` などでKPが時間を進める使い方がおすすめです。

## Minecraftの空にも連動

シナリオ時刻は全ワールドへ適用されます。
昼なら明るく、夜や深夜なら暗いMinecraft時間になります。

セッション中は通常の昼夜サイクルを止めて、
シナリオ時計の時刻に固定します。

`/session end` を実行すると通常のMinecraft昼夜サイクルへ戻ります。

## /stop time との違い

```text
/session time pause
```

は「シナリオ内の時計だけ」を止めます。

```text
/stop time
```

はPL会議などのために、PLの行動やMobなども含めてゲーム進行を停止します。

`/stop time` 中はシナリオ時計も自動で進みません。
解除するとBossBarのシナリオ時計へ戻ります。

# 追加仕様: クリティカル・スペシャル・ファンブル

能力値判定・技能判定では次のように表示されます。

```text
01～05          ★ 決定的成功 / CRITICAL ★
技能値の1/5以下 ◆ スペシャル / SPECIAL ◆
技能値以下      ○ 成功
技能値超過      × 失敗
96～100         ☠ 致命的失敗 / FUMBLE ☠
```

それぞれ結果音も異なります。

複合技能では、2つの技能それぞれに成功段階を表示し、
従来どおり成功/失敗として複合技能効果を処理します。

# 追加仕様: プレイヤーのTRPG武器攻撃

プレイヤーが素手または剣で攻撃すると、Minecraftの通常攻撃の代わりにTRPG技能判定を行います。

## 素手

```text
技能: こぶし
初期値: 50
ダメージ: 1d3+DB
```

## 剣

Minecraftの剣は「ナイフ」ではなく、新設した「刀剣」技能で判定します。

```text
技能: 刀剣
初期値: 20
```

標準ダメージ:

```text
木の剣           1d4+DB
石の剣           1d6+DB
鉄の剣           1d8+1+DB
金の剣           1d8+1+DB
ダイヤモンドの剣 1d8+1+DB
ネザライトの剣   1d8+1+DB
```

攻撃すると約1秒のダイス音のあと、命中結果とダメージが表示されます。

```text
[攻撃判定] 鉄の剣 / 技能 刀剣 55 / 1d100:31 → ○ 成功
[攻撃ダメージ] 鉄の剣 1d8+1 + DB(+1d4) → 9
```

対プレイヤーでは、最後に既存の装甲値を引いてTRPG HPへ反映します。

失敗・ファンブルではダメージは発生しません。

クリティカルは武器ダイスとDBを最大値、スペシャルは通常ダメージに+1を加える標準設定です。
この補正は `plugins/TRPGCharacter/weapons.yml` で変更できます。

武器の対応表も `weapons.yml` から編集できます。


---

# 追加仕様: マーシャルアーツ

素手や剣など、`weapons.yml` でマーシャルアーツ対象になっている近接攻撃では、
通常の命中判定と同時に「マーシャルアーツ」を自動判定します。

```text
マーシャルアーツ 初期値: 1
```

探索者シートの「戦闘」技能ページから技能値を変更できます。

例:

```text
[攻撃判定] 鉄の剣 / 刀剣 60 / 1d100:42 → 成功
[マーシャルアーツ] 技能値 35 / 1d100:21 → 成功
★ マーシャルアーツ成功！ ダメージ×2
```

通常命中技能とマーシャルアーツの両方が成功した時だけ、
武器ダメージとDB等を計算した後、装甲適用前のダメージを2倍にします。

通常の攻撃判定が失敗した場合は、マーシャルアーツだけ成功してもダメージは発生しません。

倍率や適用武器は `weapons.yml` から変更できます。


---

# 敵のTRPG戦闘バランス

主要なMinecraft Mobは `enemies.yml` によりTRPG用のHP・命中率・攻撃ダイス・装甲へ変換されます。

例:

```text
ゾンビ
HP 12
命中 45
攻撃 1d4
装甲 0
```

ゾンビが探索者を攻撃すると、

```text
[敵攻撃] ゾンビ / 命中45 / 1d100:32 → 成功
[敵ダメージ] ゾンビ 1d4 → 3 / 装甲1 / 最終2 / HP 11 → 9
```

のように処理されます。

ボスもMinecraftの数百HPではなく、TRPG戦闘向けにHP35～45程度を基本とし、
高い命中率・大きなダメージダイス・固定装甲で強さを出しています。

KPは `plugins/TRPGCharacter/enemies.yml` を変更することで各Mobを個別に調整できます。

```yaml
ZOMBIE:
  name: "ゾンビ"
  hp: 12
  hit: 45
  damage: "1d4"
  armor: 0
  player-armor: true
```

`player-armor: false` にすると、その敵の攻撃は探索者側の装甲を無視します。

設定変更後は管理者が `/status reload` を実行すると再読み込みされます。

## CoC式落下ダメージ＋跳躍自動判定

落下ダメージはMinecraft標準値ではなく、CoC6系の方式で処理します。

```text
3ブロック以下   ダメージなし
4～6ブロック    1d6
7～9ブロック    2d6
10～12ブロック  3d6
13～15ブロック  4d6
…最大8d6
```

ダメージが発生する高さから落下すると「跳躍」を自動で1d100判定します。
成功した場合は落下ダメージダイスを1個減らします。落下ダメージは装甲無効です。

4～6ブロックの落下で跳躍成功なら `1d6 → 0d6` となり、ダメージは発生しません。
この場合は跳躍判定と軽減表示だけを行い、「落下ダメージ」表示は出しません。

また、落下以外でも最終ダメージが0ならダメージメッセージを表示しません。

設定は `damage.yml` の `environment.FALL` から変更できます。

## 自動回避・連続回避ペナルティ・決定的成功反撃

Mobまたは他の探索者からTRPG戦闘の攻撃を受け、相手の命中判定が成功した場合、
被攻撃側は自動的に「回避」を判定します。

「回避」の初期値はCoC6系に合わせて `DEX×2` です。
探索者シート上で通常の技能と同様に変更できます。

標準設定では10秒以内に回避を連続使用すると成功値が低下します。

```text
1回目: 回避そのまま
2回目: -20
3回目: -40
4回目: -60
…
最低成功値: 1
```

10秒間回避を行わなければ連続回数はリセットされます。

回避結果:

```text
成功 / Special:
  攻撃を完全回避し、ダメージ0

Critical（決定的成功）:
  攻撃を完全回避
  ＋現在メインハンドに持っている登録武器で自動反撃判定

Failure / Fumble:
  通常通り攻撃ダメージを受ける
```

自動反撃でも、その武器の「こぶし」「刀剣」等の技能値で1d100を振ります。
武器がマーシャルアーツ対象なら、反撃時もマーシャルアーツを自動判定します。
手に持っているアイテムが `weapons.yml` 未登録の場合は反撃しません。

反撃に対してさらに回避→決定的成功→反撃、という無限連鎖は起こさない仕様です。

設定は `weapons.yml` の `dodge:` から変更できます。

```yaml
dodge:
  enabled: true
  skill: "dodge"
  chain-window-seconds: 10
  penalty-per-extra-use: 20
  minimum-success-value: 1
  critical-counterattack: true
```

## 継続ダメージの無敵時間

窒息、炎上、溶岩、溺れ、毒、凍結、衰弱などは `damage.yml` の
`cooldown-seconds` に従って同一原因から連続ダメージを受けないようにしています。

スイートベリーやサボテン等の `CONTACT` にも3秒のクールタイムを追加しました。
クールタイム中にMinecraft側から同じダメージイベントが繰り返し発生しても、
TRPG HPは減少しません。

## 暗所での目星自動判定・暗視

探索者が暗い場所へ入ると、自動的に「目星」を1d100判定します。

標準ではMinecraftの明るさが `4以下` の場所を暗所として扱います。

```text
明るい場所
↓
暗所へ入る
↓
目星を自動判定
↓
成功 / Special / Critical
↓
暗視状態になる
```

成功すると、暗所にいる間は暗視効果が自動で更新されます。
明るい場所へ戻ると更新が止まり、数秒後に自然に暗視が解除されます。

失敗またはFumbleの場合、その暗所に居続けている間は再判定しません。
一度明るい場所へ戻ってから再び暗所へ入ると、もう一度目星を判定します。
これにより暗所にいるだけで判定が連続して流れることを防いでいます。

設定は `config.yml` の `dark-vision:` で変更できます。

```yaml
dark-vision:
  enabled: true
  light-level-threshold: 4
  skill: "spot_hidden"
  check-interval: 10
  effect-refresh-ticks: 80
```

`light-level-threshold` は0～15で、数値を上げるほど少し明るい場所でも目星判定が発生します。

なお、回避技能の初期値 `DEX*2` を既存サーバーの `skills.yml` に自動追加する際、
数式を数値として保存しようとして失敗する可能性があった箇所も同時に修正しました。


---

## 暗所の自動目星に失敗した後の再適応

暗所へ入った際の自動「目星」に失敗した場合でも、その暗所にいる間に
探索者シートから通常の「目星」判定を行い、成功すれば暗視へ適応できます。

```text
暗所へ入る
↓
自動目星 → 失敗
↓
その場で通常の「目星」を手動判定
↓
成功
↓
暗視が発動
```

手動判定で `Success / Special / Critical` のいずれかになれば暗視が発動します。
明るい場所で目星に成功しても暗視は発動しません。

すでに暗視へ適応済みの場合は、手動目星成功による重複メッセージは表示しません。

なお、自動目星そのものは従来通り「暗所への侵入1回につき1回」なので、
失敗後に何度も自動判定が流れることはありません。

## 探索者シートの技能順

技能ページはCoC第6版の探索者シートに近い順へ整理しました。

```text
戦闘技能
↓
探索技能
↓
行動技能
↓
交渉技能
↓
知識技能
```

既存サーバーで古い `skills.yml` を使用していても、探索者シート上ではこの順番を優先して表示します。
独自追加した技能は削除せず、その技能に設定されているカテゴリの末尾へ表示します。

主な並びは次の通りです。

```text
戦闘技能:
回避 → キック → こぶし → マーシャルアーツ → 刀剣

探索技能:
応急手当 → 鍵開け → 隠す → 隠れる → 聞き耳 → 忍び歩き
→ 写真術 → 精神分析 → 追跡 → 図書館 → 目星

行動技能:
運転 → 機械修理 → 重機械操作 → 乗馬 → 水泳 → 芸術 → 製作
→ 操縦 → 跳躍 → 電気修理 → ナビゲート → 変装

交渉技能:
言いくるめ → 信用 → 説得 → 値切り → 母国語

知識技能:
医学 → オカルト → 化学 → クトゥルフ神話 → 経理 → 考古学
→ コンピューター → 心理学 → 人類学 → 生物学 → 地質学
→ 天文学 → 博物学 → 物理学 → 法律 → 薬学 → 歴史 → 他の言語
```

## 素手攻撃の「こぶし / キック」選択

メインハンドが空の状態で敵を攻撃すると、すぐには判定せずチャットに選択肢を表示します。

```text
素手攻撃を選択: [こぶし] [キック]
```

5秒以内にどちらかをクリックすると、最初に殴った対象へ選択した技能で攻撃判定を行います。

```text
こぶし
初期値 50
ダメージ 1d3 + DB

キック
初期値 25
ダメージ 1d6 + DB
```

どちらもマーシャルアーツ自動判定の対象です。
マーシャルアーツに成功した場合は、従来通り装甲適用前ダメージへ倍率を適用します。

選択待ちの間に対象が5ブロックより離れる、対象が死亡する、武器を持つ、
または5秒を超えるとその素手攻撃はキャンセルされます。

「キック」は独立した戦闘技能として探索者シートに追加され、通常の技能と同様に技能値を変更できます。

## 素手攻撃を探索者シートで事前設定

素手攻撃は、攻撃するたびに「こぶし / キック」を選ぶ方式ではありません。

探索者シートの「戦闘設定」ページで、あらかじめ使用する素手攻撃を設定します。

```text

素手攻撃
現在: こぶし

[✓ こぶし] [キック]
```

または、

```text
戦闘設定

素手攻撃
現在: キック

[こぶし] [✓ キック]
```

選択画面を挟まず、その場で設定済みの技能による攻撃判定を開始します。

```text

技能「こぶし」
1d3 + DB

キック:
技能「キック」
1d6 + DB
```

どちらもマーシャルアーツの自動判定対象です。

この設定は `players.yml` に探索者ごとに保存されるため、
ログアウトやサーバー再起動後も維持されます。

まだ一度も設定していない探索者は「こぶし」が初期選択になります。

## 神話生物NPC

神話生物専用の `mythos-creatures.yml` を追加しました。
通常のMinecraft Mobとは別管理で、KPが召喚した個体だけが神話生物になります。

最初の神話生物として「深きもの」を実装しています。

```text
/mythos list
/mythos summon deep_one
/mythos sanreset <player>
```

`/mythos summon deep_one` では、KPの前方に深きもの（DROWNEDベース）を召喚します。

深きもの初期設定:

```text
HP 13
装甲 1
命中 25
攻撃 1d6
SANチェック 0 / 1d6
```

召喚された深きものにはPDCで `deep_one` が保存されるため、
通常スポーンしたDROWNEDは従来どおり普通のMobとして扱われます。

探索者が設定距離内で初めて深きものを視認すると、自動的にSANチェックを行います。
同じ探索者に対して同じ種類の神話生物では連続SANチェックを行いません。
テストなどで再度判定したい場合は `/mythos sanreset <player>` を使用します。

今後は `mythos-creatures.yml` にグール、ミ＝ゴなどを追加できる構造です。


## 水中での自動「水泳」判定

暗所での自動目星と同じ考え方で、水中へ入ったときに一度だけ「水泳」を自動判定します。

```text
[水中] 水泳判定 / 技能値 25 / 1d100:18 → 成功
水泳成功！ 水中で素早く泳げるようになりました。
```

成功すると、水中にいる間 `DOLPHINS_GRACE` を短時間ずつ更新し、
通常より速く泳げるようになります。

失敗した場合、同じ水中に居続けている間は自動再判定しません。
一度水から出て入り直すと再判定できます。

また、自動判定に失敗した後でも、水中で探索者シートから手動の「水泳」判定に成功すれば、
暗所目星の救済処理と同様に泳速強化が有効になります。

設定は `config.yml` の `auto-swim` で変更できます。

## 技能ポイント：趣味ポイント

CoC第6版の趣味技能ポイントを実装しました。

### 計算

```text
趣味ポイント = INT × 10
```

探索者シートに「技能ポイント」ページが追加され、次の内容を確認できます。

```text
技能ポイント

趣味ポイント
合計: 140
使用: 30
残り: 110
計算: INT×10

[趣味ポイントをリセット]

職業ポイント: 未実装
```

各技能ページでは従来の `[変更]` の代わりに `[趣味+]` が表示されます。

```text
目星 45 (趣+20) [趣味+] [判定]
聞き耳 35 (趣+10) [趣味+] [判定]
```

`[趣味+]` を押すと、その技能へ何ポイント割り振るかチャット入力します。

```text
/trpgskill hobby <技能ID>
```

割り振り時は以下を自動チェックします。

- 残り趣味ポイントを超えて割り振れない
- 0以下は割り振れない
- 最終技能値は99を上限とする
- 初期技能値は消費ポイントに含めない
- 趣味ポイントは技能ごとに個別保存する

割り振った趣味ポイントだけをすべて戻したい場合:

```text
/trpgskill hobby-reset
```

リセットしても能力値、HP/MP/SAN、技能の初期値・KPによる直接設定値などは削除しません。

### 将来の職業ポイント

保存構造はあらかじめ、

```text
skill-points:
  hobby:
    allocations:
  occupation:
    allocations:
```

のように趣味・職業を分離しています。

最終技能値は、

```text
技能初期値
+ 趣味ポイント割振り
+ 職業ポイント割振り（将来）
= 最終技能値
```

という構造です。

職業システム実装時には、職業ごとの対象技能と職業ポイント計算を追加し、
趣味ポイントとは別枠で割り振れるようにできます。

## 接触系継続ダメージのクールダウン修正

サボテン・スイートベリー等の `CONTACT` ダメージで、
TRPG HPが短時間に連続して減る場合がある問題を修正しました。

変更前は、最終ダメージをHPへ反映した後にクールダウンを登録していました。
変更後は、最初の有効な接触イベントを受け付けた時点でクールダウンを登録します。

標準設定:

```yaml
CONTACT:
  name: "接触（ベリー・サボテン等）"
  damage: "1d3"
  armor: true
  cooldown-seconds: 3
```

そのため、接触し続けていても原則として3秒に1回だけTRPGダメージ判定が行われます。

また、装甲によって最終ダメージが0になった場合でも、
その接触イベントから3秒間は次のCONTACTダメージを受けません。

FIRE/FIRE_TICK、LAVA、DROWNING、SUFFOCATION、POISON、WITHER等の
既存クールダウン処理も同じ「最初のイベント時点で開始」方式になり、
継続ダメージ全体の連続発生をより安定して防止します。

## アーティファクトシステム

神話的な特殊アイテムを実装するための汎用アーティファクト基盤を追加しました。

アーティファクトは通常のMinecraftアイテムとは別物です。
配布時にPDCで固有IDが保存されるため、同じ素材の通常アイテムが
アーティファクトとして誤認されることはありません。

### KP・管理者コマンド

```text
/artifact list
/artifact give <player> <id>
/artifact remove <player> <id>
```

### テスト実装: 古き印

初期アーティファクトとして `elder_sign`（古き印）を追加しています。

```text
/artifact give <player> elder_sign
```

初期設定:

```text
素材: PAPER
常時効果:
  神話生物から受ける最終ダメージ -1

右クリック効果:
  周囲8ブロックの神話生物を退ける
  SAN消費 1
  クールダウン 30秒
  効果時間 5秒
```

右クリック効果の `REPEL_MYTHOS` は、
`/mythos summon` などで神話生物として登録された個体だけを対象にします。
通常のゾンビ、ドラウンド等には作用しません。

発動時には周囲の神話生物をプレイヤーから遠ざけ、
一定時間発光させて対象を視認しやすくします。

時間停止中はPLによるアーティファクト使用も停止します。
KP・OP・管理者は時間停止中でも通常どおり操作できます。

### artifacts.yml

今後は `plugins/TRPGCharacter/artifacts.yml` に新しい項目を追加することで、
アーティファクトを増やせる構造です。

```yaml
artifacts:
  elder_sign:
    name: "古き印"
    material: PAPER
    description:
      - "名状しがたい存在を退けるための印。"

    passive:
      mythos-damage-reduction: 1

    active:
      enabled: true
      cooldown-seconds: 30
      san-cost: "1"
      effect:
        type: REPEL_MYTHOS
        range: 8.0
        duration-seconds: 5
```

SAN消費は固定値だけでなく `1d3` や `1d6+1` の形式にも対応しています。

今後、効果タイプを追加することで、
HP/MP/SAN消費、技能判定、回復、攻撃、神話生物特効、
一時的な能力強化などへ拡張できます。

## クリティカル・ファンブル時の自動技能成長

技能判定でクリティカルまたはファンブルが発生すると、
その技能について自動で成長判定を行います。

初期設定では次の方式です。

```text
1. 技能判定でクリティカルまたはファンブル
2. 自動で1d100の成長判定
3. 1d100 > 現在技能値 なら成長成功
4. 成長成功時 1d10 上昇
5. 技能値上限は99
```

例:

```text
[CoC判定] 目星 目標値:55 / 1d100:03 → クリティカル
[技能成長判定] 目星 現在値:55 / 1d100:82 → 成長成功
★ 技能成長！ 目星 55 → 62 (+7)
```

成長値は `players.yml` の `skill-growth.allocations` に
趣味ポイント・将来の職業ポイントとは別枠で保存されます。

そのため最終技能値は、

```text
技能初期値
+ 趣味ポイント
+ 職業ポイント（将来）
+ 技能成長値
= 最終技能値
```

となります。

趣味ポイントのリセットを行っても技能成長値は消えません。
探索者データ自体を `/reset pc` で初期化した場合は成長値も初期化されます。

対象には通常の技能判定のほか、
戦闘技能、マーシャルアーツ、回避、複合技能、
暗所の自動目星、水泳の自動判定、落下時の跳躍判定も含まれます。

`/roll`、能力値判定、派生判定、SAN判定、敵側の命中判定には
技能成長は発生しません。

設定:

```yaml
skill-growth:
  enabled: true
  trigger-critical: true
  trigger-fumble: true
  increase: "1d10"
  max-skill-value: 99
```

`increase` は `1d6`、`1d10+2`、固定値 `3` などへ変更できます。

## 壁キック（登攀）

壁に密着してジャンプし、短時間のうちにもう一度ジャンプ操作を行うと「登攀」判定を行います。
成功すると壁から離れる方向＋上方向へ跳びます。スペシャル/クリティカルでは跳躍力が上がり、
ファンブルでは体勢を崩して下方向へ押し戻されます。発動後は短いクールダウンがあります。
地上での通常ジャンプ連打では発動せず、壁の近くにいる時だけ候補になります。
`/stop time` 中に行動できないPL、死亡中、スペクテイター、水中では使用できません。
この登攀判定のクリティカル/ファンブルは既存の技能成長システムにも接続されています。

Paper/Bukkitにはスペースキーそのものの押下イベントがないため、
ジャンプ開始と壁際での空中上向き速度変化から2回目の入力相当を検出します。


### 探索者シートの技能ボタン表示改善

技能名・技能値・趣味ポイント表示が長い場合でも `[趣味+]` と `[判定]` が
本の右端へはみ出さないよう、技能情報と操作ボタンを別行に表示します。
1ページの技能数も5件から4件へ減らし、刀剣・聞き耳・図書館などでも
クリック領域が安定して表示されるようにしています。

## 接触系の連続ダメージを0に変更

スイートベリー、サボテン、マグマブロックなど、短い間隔で何度も
ダメージイベントが発生するものはTRPG HPを減らさない仕様にしています。

既定で0ダメージになるDamageCause:
- `CONTACT`（スイートベリー、サボテン等）
- `HOT_FLOOR`（マグマブロック）

Minecraft側の通常ダメージもキャンセルされるため、これらに触れてもHPは減りません。
既存サーバーの古い `damage.yml` を使っている場合でも、この2種類は既定で0になります。
対象は `damage.yml` の `zero-damage-causes` で変更できます。


### 暗視の点滅対策
暗所適応の暗視効果を短時間（従来約4秒）で継ぎ足す方式から、
十分長い60秒の効果を維持する方式へ変更しました。
Minecraftの暗視効果は残り時間が短くなると画面が点滅するため、
これにより暗所滞在中のチカチカを抑えます。
明るい場所へ出た場合は暗視を即時解除します。


### 二段ジャンプ・登攀の移動技能
従来の壁キックを廃止し、Paper/Bukkitで安定して2回目のスペース入力を取得できる `PlayerToggleFlightEvent` 方式の二段ジャンプへ変更しました。実際の飛行は開始せず、跳躍判定成功時だけ空中で追加ジャンプします。

登攀は壁に向かって移動し続けると自動で登攀判定を行い、成功すると一定時間、蜘蛛のように壁へ吸着しながら上昇できます。壁から離れる・着地する・水に入ると終了します。クリティカル/スペシャルでは登攀可能時間が延長されます。

- `silver_key` 銀の鍵
  - 初回右クリックで現在地を記憶（代償なし）。
  - 以後 SAN 1d3 + MP5 でワールドを越えて記憶地点へ移動。
  - クールダウン30分。使用回数が増えると時折、不穏な門の演出が発生。

配布は `/artifact give <player> <id>` を使用します。


## アーティファクト右クリック修正

新規4種の発動入力を修正しました。
- メインハンドのみを判定し、オフハンドによる二重発動を防止。
- `PlayerInteractEvent` が他の処理でcancel扱いになっていても、アーティファクト自身の判定を実行。
- イゴーロナクの手は `PlayerInteractEntityEvent` にも対応し、対象プレイヤーを直接右クリックして発動可能。
- 輝くトラペゾヘドロン、夢のクリスタライザー、銀の鍵は通常の右クリックで発動。


## ドリームランド・ディメンション

Paper 1.20.1上では、安定性を優先して専用ワールド `dreamlands` を別ディメンションとして扱います。

### 睡眠による移動
- 通常世界でプレイヤーがベッドで「深い睡眠」に入った時だけ判定します。
- 初期転移率は10%です。
- `/dreamland chance <0-100>` でKP/管理者が即時変更できます。
- `0` にすると睡眠からは一切転移しません。
- `/dreamland enable off` にすると睡眠・夢のクリスタルライザーを含むドリームランド機能そのものを停止できます。
- 初期設定ではアクティブなセッションがある時だけ自動転移します。
- 転移前のワールド・座標・向きを `dreamlands.yml` に保存するため、サーバー再起動後も帰還先を保持します。

### 帰還
- ドリームランド内で再び深く眠ると、保存されている現実側の地点へ戻ります。
- KPは `/dreamland return <player>` で強制帰還できます。
- KPは `/dreamland tp <player>` で強制的にドリームランドへ送れます。

### KPコマンド
- `/dreamland status` 現在の設定を表示
- `/dreamland chance <0-100>` 睡眠転移率を変更
- `/dreamland enable <on|off>` ドリームランド機能全体をON/OFF
- `/dreamland tp <player>` 強制転移
- `/dreamland return <player>` 強制帰還

KPブックにもドリームランド専用ページを追加しています。

### 夢のクリスタルライザー
旧版の「記憶地点ワープ」からドリームランド連携へ変更しました。
右クリックするとSAN 1d3 + MP3を消費し、ドリームランドへ直接移動します。
`dreamlands.enabled: false` またはセッション必須条件を満たさない場合は発動せず、SAN/MPも消費しません。
既存サーバーの旧 `DREAM_ANCHOR` 設定は起動時に自動移行します。


## ドリームランド神話地形

ドリームランド専用ワールドを、通常のMinecraft地形ではなくクトゥルフ神話TRPG向けの幻想的な専用地形へ変更しました。

### 地形の特徴
- 黒い海と急峻な岸壁
- 不自然に隆起する山稜
- 深い裂け目
- ディープスレート、ブラックストーン、玄武岩、凝灰岩を中心とした暗い地表
- スカルク、ソウルサンド、ソウルソイルが混ざる異様な低地
- 黒曜石と泣く黒曜石でできた細長い遺構
- ワープドファンガス、キノコ、スカルク系の異様な植生
- Deep Dark、Basalt Deltas、Soul Sand Valley等のバイオーム色を利用した寒色・暗色寄りの景観
- 原点周辺だけは初回転移で落下しにくい安全な高台

専用ワールド名は新規環境では `dreamlands_mythos` です。

旧版の `dreamlands` ワールドが存在するサーバーでは、古いワールドを削除せずに `dreamlands_mythos` を新規生成して自動移行します。そのため既存ワールドを破壊しません。

この地形は外部ワールド生成プラグインに依存せず、Paper/Bukkit標準のChunkGeneratorで生成します。


## ドリームランド専用生物

ドリームランドではゾンビ、クリーパー、スケルトン、通常の動物などの通常Mobは自然発生しません。
自然発生・チャンク生成・スポナー・増援などによる通常Mob生成を遮断し、プラグインが管理するドリームランド神話生物だけを自然発生させます。

実装済みの6種:
- `nightgaunt` ナイトゴーント（Phantomベース）
- `gug` ガグ（Endermanベース）
- `moon_beast` ムーンビースト（Ravagerベース）
- `zoog` ズーグ（Silverfishベース）
- `spider_of_leng` レンの蜘蛛（Cave Spiderベース）
- `shantak` シャンタク鳥（Phantomベース）

これらは既存の神話生物システムに登録されるため、TRPG用HP・命中・ダメージ・装甲・遭遇時SANチェックが適用されます。
既存サーバーの `mythos-creatures.yml` に6種が存在しない場合は、起動・リロード時に標準設定を自動補完します。

自然スポーンはプレイヤー周囲18～34ブロックを基準に行い、近くに最大6体まで出現します。
高所ではナイトゴーント/シャンタク鳥、暗い低地ではガグ/レンの蜘蛛がやや出やすくなっています。

KPコマンド:
- `/dreamland mobs on` ドリームランド生物の自然スポーンON
- `/dreamland mobs off` ドリームランド生物の自然スポーンOFF
- `/dreamland mobs rate <0-100>` スポーン抽選率変更
- `/dreamland status` 現在のスポーン設定も表示

`/mythos summon <id>`、`/summon`、スポーンエッグ等のKP/管理者による手動演出は遮断しません。

## 青紫の異界月・常時夜

ドリームランドは `dreamlands.always-night: true` により常時夜になります。
通常世界の時間は変更しません。

リソースパックなしで、TextDisplayを3層重ねた巨大な青紫の異界月を表示します。
月は各プレイヤー専用表示で、プレイヤーが移動しても遠い空に留まるよう追従します。
通常世界へ帰還すると自動的に消えます。

設定:
- `dreamlands.moon.enabled`: 異界月のON/OFF
- `dreamlands.moon.scale`: 月の大きさ。標準18.0、範囲2～40
- `dreamlands.moon.horizontal-distance`: 横方向の距離
- `dreamlands.moon.height-offset`: 高さ
- `dreamlands.moon.update-interval-ticks`: 追従更新間隔

`/status reload` で月設定も再読込されます。
